# PRD — 힐링 및 기원 사이트 「산사의 마음」

> 원본: `PRD_바이브코딩 메인쿼스트.docx` · 이 문서는 원본 요구사항과 실제 구현 내용을 함께 기록합니다.

## 1. 프로젝트 개요
- **프로젝트명**: 힐링 및 기원 사이트 (서비스명: 산사의 마음)
- **개발 목적**: 절에 들어가 템플스테이 및 자녀 수능/시험 합격 기원을 요청할 수 있는 사이트를 만들어 온라인에서 수양 및 기원드릴 수 있도록 한다.
- **대상 사용자**: 템플스테이로 힐링하고 싶은 사람 / 자녀 수능·시험 합격을 기원하고 싶은 사람
- **기대 효과**: 마음의 평화를 얻을 수 있도록

## 3. 개발 요구사항 대응
- **로컬 구현 후 배포** (처음엔 GitHub Pages, 이후 사용자 요청으로 Render 로 일원화): Supabase 키가 없으면 SQLite 로 동작 → 로컬 즉시 테스트. `frontend/` 는 정적 파일만으로 구성(해시 라우팅)되어 GitHub Pages 에 그대로 배포. 워크플로 `.github/workflows/pages.yml` 포함.
- **모바일 지원**: 반응형 레이아웃(375px 기준 확인), 터치로 울력(문지르기)·절 올리기 가능, safe-area 대응.
- **문서화**: README.md, 본 PRD, SECURITY_CHECK.md.
- **보안 점검**: `docs/SECURITY_CHECK.md` 참고.
- **디자인**: 손그림·아늑함 — 한지 질감 배경, 붓글씨(Nanum Brush Script)·손글씨(Gaegu)·바탕(Gowun Batang) 서체, 단청 색(주홍·청록·황토), SVG 흔들림 필터로 그린 선, 나무 현판 버튼, 인장, 마스킹테이프 메모, 연등 줄.
  ※ 요청서의 `frontend-design` 스킬은 이 환경에 없어, 같은 원칙(분위기에 맞는 개성 있는 디자인, 흔한 AI 스타일 회피)으로 직접 디자인했습니다.

## 4. 기술 스택

| 구분 | 요구 | 구현 |
|---|---|---|
| 개발 언어 | Python | 백엔드 FastAPI (Python 3.12+) / 프론트엔드 Vanilla JS (빌드 불필요) |
| 백엔드 & DB | Supabase | Supabase Auth + Postgres(RLS) |
| Web service | Render | 무료 Web Service 하나가 웹사이트+API 제공 (Blueprint 미사용) |
| DB 접속 방식 | API 통해서 | 브라우저 → Render API → Supabase REST(PostgREST)·Auth API. 브라우저는 DB에 직접 접속하지 않음 |

```
[브라우저] --HTTPS--> [FastAPI: Render (웹사이트 + /api)] --REST(사용자 JWT)--> [Supabase Auth / Postgres + RLS]
```

## 6. 개발 기록

### 2026-11-03 — 1차 구현
- PRD 분석 후 구조 결정: 정적 프론트(GitHub Pages) + Python API(Render) + Supabase.
  GitHub Pages 는 서버 코드를 돌릴 수 없으므로 Python 은 Render 의 API 서버로 사용.
- 백엔드: FastAPI, 백엔드 추상화(Supabase / 로컬 SQLite) 두 구현, 입력 검증(Pydantic), 요청 제한, 보안 헤더.
- Supabase 스키마: 3개 테이블 + RLS(본인 행만) + 공유 편지 security definer 함수.
- 프론트엔드: 해시 라우터 SPA, 사찰 5곳 손그림 SVG 생성기, 템플스테이 7단계 인터랙션, 소원·절·편지, 나의 기록.
- 오디오: Web Audio 로 목탁·범종·지속음 합성, 반야심경 독송문 표시. mp3 를 넣으면 자동으로 그 음원을 사용.
- 브라우저 테스트(로컬 모드): 가입 → 사찰 → 템플스테이 7단계 완료 → 수료 / 소원 3배 → 편지 → 로그아웃 상태에서 공유 링크 열람 / 나의 기록, 모바일(375px) 화면.
- 테스트 중 수정한 버그
  - 울력 캔버스: 지우개 색이 반투명이라 잘 안 지워지던 문제 → 불투명 색으로 지움, 손을 뗄 때도 진척도 확인.
  - 로고 `.seal` 클래스가 인장 버튼 `.btn.seal` 과 충돌 → `.logo-seal` 로 분리.
  - `hidden` 속성이 `display` 지정 요소에서 무시되던 문제 → 전역 `[hidden]{display:none!important}`.
  - 편지 제목 조사 오류(가족를) → 대상별 목적격 조사 표기.
  - ES 모듈 캐시로 옛 파일이 섞이던 문제 → 로컬 서버 정적 파일 `Cache-Control: no-cache`.

### 2026-11-03 — 가입 오류 수정
- 증상: 운영 사이트에서 신규 가입이 계속 실패(API 401).
- 원인: Supabase Auth 로그 `429 email rate limit exceeded (over_email_send_rate_limit)`. 기본 메일 발송은 시간당 몇 통만 허용되어, 가입 확인 메일이 막히면 가입 자체가 취소됨.
- 조치: 사용자 승인 후 Supabase **Confirm email 끄기** → 확인 메일 없이 가입 즉시 로그인(PRD "이메일 가입·최소 개인정보" 범위).
  API 는 Supabase 오류 코드별 안내(메일 한도 429, 이미 가입 409, 쉬운 비밀번호, 미인증 로그인)를 보여 주도록 수정.
